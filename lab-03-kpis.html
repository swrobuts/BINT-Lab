DAX GrundlagenDAX Fundamentals

DAX (Data Analysis Expressions) ist eine Excel-ähnliche Formelsprache, die speziell für Power BI, Analysis Services und Power Pivot entwickelt wurde. Mit DAX können Sie leistungsstarke Berechnungen und Analysen direkt im Datenmodell definieren.DAX (Data Analysis Expressions) is an Excel-like formula language developed specifically for Power BI, Analysis Services and Power Pivot. With DAX you can define powerful calculations and analyses directly in the data model.

Was ist DAX?What is DAX?

DAX ist eine Sammlung von Funktionen, Operatoren und Konstanten, die in Formeln (Expressions) verwendet werden können, um einen oder mehrere Werte zu berechnen. DAX wurde für die Arbeit mit Tabellen und Beziehungen optimiert und kennt zwei wichtige Konzepte: Measures und Calculated Columns.DAX is a collection of functions, operators and constants that can be used in formulas (expressions) to calculate one or more values. DAX is optimised for working with tables and relationships and has two important concepts: Measures and Calculated Columns.

Measures vs. Calculated Columns

Measures (Kennzahlen)Measures (Metrics)
  • Dynamisch – werden zur Laufzeit berechnetDynamic – calculated at runtime
  • Abhängig vom aktuellen Filter-KontextDependent on the current filter context
  • Werden NICHT in der Tabelle gespeichertNOT stored in the table
  • Beispiele: Gesamtumsatz, Marge %, YoY-WachstumExamples: Total Revenue, Margin %, YoY Growth
Calculated Columns
  • Werden bei jeder Datenaktualisierung neu berechnetRecalculated on every data refresh
  • Zeile für Zeile im Row Context ausgewertetEvaluated row by row in the row context
  • Ergebnis wird im Modell gespeichert und belegt SpeicherResult is stored in the model and consumes memory
  • Beispiele: Vollständiger Name, Kategorie-GruppeExamples: Full Name, Category Group

Goldene RegelGolden Rule

Fast immer Measures verwenden! Measures sind flexibler, verbrauchen weniger Speicher und reagieren korrekt auf Filter. Calculated Columns nur verwenden, wenn Sie den Wert in Slicern oder als Filterbedingung benötigen.Almost always use Measures! Measures are more flexible, consume less memory and respond correctly to filters. Use Calculated Columns only when you need the value in slicers or as a filter condition.

DAX Code

-- Einfache Aggregation
Gesamtumsatz = SUM(Umsatz[Betrag])

-- Mit Bedingung (CALCULATE)
Umsatz_DE = CALCULATE(SUM(Umsatz[Betrag]), Umsatz[Land] = "Deutschland")

-- Division mit Null-Absicherung
-- Hinweis: [Bruttogewinn] muss als eigenes Measure existieren, z.B.
-- Bruttogewinn = SUM(Umsatz[Gewinn])
Marge_% = DIVIDE([Bruttogewinn], [Gesamtumsatz], 0) * 100

-- Zeitintelligenz
Umsatz_VJ = CALCULATE([Gesamtumsatz], SAMEPERIODLASTYEAR(Datum[Datum]))
Wachstum_% = DIVIDE([Gesamtumsatz] - [Umsatz_VJ], [Umsatz_VJ], 0) * 100

-- Ranking
Top_Produkte = RANKX(ALL(Produkt[Name]), [Gesamtumsatz], , DESC, Dense)
-- Simple aggregation
TotalRevenue = SUM(Sales[Amount])

-- With condition (CALCULATE)
Revenue_DE = CALCULATE(SUM(Sales[Amount]), Sales[Country] = "Germany")

-- Division with zero protection
-- Note: [GrossProfit] must exist as its own measure, e.g.
-- GrossProfit = SUM(Sales[Profit])
Margin_% = DIVIDE([GrossProfit], [TotalRevenue], 0) * 100

-- Time intelligence
Revenue_PY = CALCULATE([TotalRevenue], SAMEPERIODLASTYEAR(Date[Date]))
Growth_% = DIVIDE([TotalRevenue] - [Revenue_PY], [Revenue_PY], 0) * 100

-- Ranking
Top_Products = RANKX(ALL(Product[Name]), [TotalRevenue], , DESC, Dense)

SMART-KPI-FrameworkSMART KPI Framework

Gute KPIs erfüllen die SMART-Kriterien (Doran, 1981): Specific – klar definiert und eindeutig messbar; Measurable – quantifizierbar mit konkreten Metriken; Achievable – realistisch erreichbar; Relevant – strategisch bedeutsam für das Unternehmensziel; Time-bound – mit klarem Zeithorizont (z. B. monatlich, quartalsweise).Good KPIs meet the SMART criteria (Doran, 1981): Specific – clearly defined and unambiguously measurable; Measurable – quantifiable with concrete metrics; Achievable – realistically attainable; Relevant – strategically significant for business goals; Time-bound – with a clear time horizon (e.g. monthly, quarterly).

Leading vs. Lagging Indicators

Lagging Indicators messen vergangene Ergebnisse (Umsatz, Gewinn, Churn Rate). Leading Indicators sind Frühwarn-Kennzahlen, die zukünftige Ergebnisse vorhersagen (Website-Traffic, Pipeline-Volumen, Kundenzufriedenheit). Eine gute KPI-Strategie kombiniert beide Typen.Lagging indicators measure past outcomes (revenue, profit, churn rate). Leading indicators are early-warning metrics that predict future results (website traffic, pipeline volume, customer satisfaction). A sound KPI strategy combines both types.

Filter-KontextFilter Context

Das Verständnis des Filter-Kontexts ist der Schlüssel zu machtvollem DAX. Es gibt zwei grundlegende Kontexte in DAX:Understanding the filter context is the key to powerful DAX. There are two fundamental contexts in DAX:

Row Context (Zeilen-Kontext)Row Context

Beim Row Context iteriert DAX Zeile für Zeile über eine Tabelle. Dieser Kontext entsteht automatisch bei Calculated Columns und bei Iterator-Funktionen wie SUMX, AVERAGEX, MAXX. In jedem Durchlauf ist die aktuelle Zeile bekannt.In Row Context, DAX iterates row by row over a table. This context is automatically created for Calculated Columns and for iterator functions like SUMX, AVERAGEX, MAXX. In each iteration the current row is known.

Filter Context (Filter-Kontext)Filter Context

Der Filter Context ist die Menge aller aktiven Filter, wenn ein Measure ausgewertet wird. Diese Filter entstehen durch Slicers, Report-Filter, Zeilen/Spalten in einer Matrix oder durch CALCULATE()-Aufrufe im DAX-Code selbst.The Filter Context is the set of all active filters when a Measure is evaluated. These filters are created by slicers, report filters, rows/columns in a matrix or by CALCULATE() calls in the DAX code itself.

Warum CALCULATE() so mächtig istWhy CALCULATE() is so powerful

CALCULATE() ist die zentrale Funktion, um einen skalaren Ausdruck in einem geänderten Filterkontext auszuwerten: Filter hinzufügen, entfernen oder überschreiben – direkt in einer Formel. Das Gegenstück für Tabellenausdrücke ist CALCULATETABLE(); daneben wirken Filtermodifikatoren wie ALL(), REMOVEFILTERS() oder KEEPFILTERS() auf den Kontext. In einem Measure führt der Weg zu eigenen Filtern aber praktisch immer über CALCULATE.CALCULATE() is the central function for evaluating a scalar expression in a modified filter context: add, remove or override filters – directly in a formula. Its counterpart for table expressions is CALCULATETABLE(); filter modifiers such as ALL(), REMOVEFILTERS() and KEEPFILTERS() also act on the context. Inside a measure, however, the route to your own filters is practically always CALCULATE.

-- Ohne CALCULATE: bestehende Filter gelten, aber
-- man kann keine NEUEN Filter hinzufügen
Umsatz_einfach = SUM(Umsatz[Betrag])  -- respektiert aktive Slicer/Filter

-- Mit CALCULATE: Filter-Kontext gezielt ändern
Umsatz_DE = CALCULATE(
    SUM(Umsatz[Betrag]),
    Umsatz[Land] = "Deutschland"   -- neuer Filter wird hinzugefügt
)

-- Filter entfernen mit ALL()
Umsatz_Gesamt_Immer = CALCULATE(
    SUM(Umsatz[Betrag]),
    ALL(Umsatz)                    -- ALLE Filter auf Umsatz entfernt
)

-- Anteil am Gesamtumsatz
Anteil_% = DIVIDE(
    [Gesamtumsatz],
    CALCULATE([Gesamtumsatz], ALL(Umsatz[Land])),
    0
)

-- VAR / RETURN (modernes DAX-Pattern)
-- Setzt voraus: Gesamtkosten = SUM(Umsatz[Kosten])
Gewinnmarge =
    VAR _umsatz = [Gesamtumsatz]
    VAR _kosten = [Gesamtkosten]
    RETURN
        DIVIDE(_umsatz - _kosten, _umsatz, 0)
-- Without CALCULATE: existing filters apply, but
-- you cannot ADD new filters
Revenue_simple = SUM(Sales[Amount])  -- respects active slicers/filters

-- With CALCULATE: modify filter context explicitly
Revenue_DE = CALCULATE(
    SUM(Sales[Amount]),
    Sales[Country] = "Germany"     -- new filter is added
)

-- Remove filter with ALL()
Revenue_Always_Total = CALCULATE(
    SUM(Sales[Amount]),
    ALL(Sales)                     -- ALL filters on Sales removed
)

-- Share of total revenue
Share_% = DIVIDE(
    [TotalRevenue],
    CALCULATE([TotalRevenue], ALL(Sales[Country])),
    0
)

-- VAR / RETURN (modern DAX pattern)
-- Requires: TotalCost = SUM(Sales[Cost])
ProfitMargin =
    VAR _revenue = [TotalRevenue]
    VAR _cost    = [TotalCost]
    RETURN
        DIVIDE(_revenue - _cost, _revenue, 0)

Dieselben KPIs in TableauThe same KPIs in Tableau

Tableau kennt kein CALCULATE. Was in DAX der Filterkontext ist, verteilt sich hier auf zwei Werkzeuge: Level-of-Detail-Ausdrücke legen die Ebene fest, auf der gerechnet wird, Tabellenberechnungen rechnen über das, was die Ansicht bereits zeigt. Wer diesen Unterschied verstanden hat, liest beide Sprachen.Tableau has no CALCULATE. What DAX calls filter context is split across two tools here: level-of-detail expressions set the level at which a value is computed, table calculations compute across what the view already shows. Understand that difference and you can read both languages.

LOD oder Tabellenberechnung?LOD or table calculation?

Die Faustregel steckt in der Reihenfolge, in der Tableau rechnet: Ein FIXED-Ausdruck entsteht, bevor die Filter der Ansicht greifen – sein Ergebnis bleibt stabil, egal was gerade sichtbar ist. Eine Tabellenberechnung entsteht danach und sieht nur noch, was die Ansicht zeigt. Der Anteil der Region West beträgt mit FIXED immer 31,4 %; mit TOTAL() ist es der Anteil an den gerade sichtbaren Regionen. Beide Zahlen sind richtig – sie beantworten verschiedene Fragen.The rule of thumb follows Tableau order of operations: a FIXED expression is computed before the filters of the view apply, so its result stays stable no matter what is visible. A table calculation happens afterwards and only sees what the view shows. The share of the West region is always 31.4% with FIXED; with TOTAL() it is the share of the regions currently visible. Both numbers are correct – they answer different questions.
